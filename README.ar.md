# ZakiCode

‏ZakiCode هو نسخة شخصية (fork) من ZCode تركّز على بيئات تشغيل معزولة داخل sandbox لمساحات عمل الوكيل (Agent). مشروع ZCode الأصلي هو مساحة عمل برمجية مدعومة بالذكاء الاصطناعي بواجهات سطح مكتب ومتصفح وطرفية (Terminal). يحتوي هذا المستودع على العملاء، والخدمات الخلفية، وواجهة المستخدم المشتركة، إضافة إلى شيفرة مصدر واجهة سطر الأوامر للوكيل ووقت التشغيل الخاص به.

| الواجهة                | الغرض                                                                             | أمر التطوير                    |
| ---------------------- | --------------------------------------------------------------------------------- | ------------------------------ |
| Desktop                | تطبيق سطح مكتب مبني على Electron                                                  | `pnpm dev:desktop`             |
| Web / توزيعة ZCode CLI | مساحة عمل طرفية ومتصفح؛ تجمّع TUI وعميل Web والخدمة الخلفية والوكيل في حزمة واحدة | `pnpm dev:web`                 |
| Agent CLI              | واجهة `zcode` للطرفية، وتوفر أيضًا وقت تشغيل الوكيل لكلٍّ من Desktop و Web        | `pnpm --filter @zcode/cli dev` |

## ما تضيفه هذه النسخة

نقاط ألمي الخاصة، محلولة (ملاحظات التصميم في `docs/`):

> **ملاحظة عن الأساس:** هذه النسخة مبنية على **ZCode مفتوح المصدر**، وهو يفتقد ميزات موجودة في النسخة المغلقة — مثل التحكم عن بعد من الموبايل ومكافأة الـ +150% في الحصة وحسابات مشابهة؛ فهي ليست جزءًا من هذا المستودع. كل ما يلي مضاف فوق الأساس المفتوح.

### كمبيوتر معزول لكل مشروع

**Projects +** ← **Open folder in VM**. أول استخدام: يبني التطبيق الـ base image تلقائيًا (الافتراضي: docker وpython وnode وgh — وأدوات agent-vm الأساسية الدائمة مثل git وripgrep وbuild-essential تأتي دائمًا). كل VM مشروع نسخة منها. تعرض اللوحة الحجم الافتراضي (1 vCPU / 3 GB / 10 GB) بجانب الذاكرة الحرة الحقيقية لجهازك قبل الضغط — كبّر كما تريد.

داخل العزل: للوكيل صلاحية كاملة — docker وتثبيتات وبلا مطالبات أذونات. جهازك لا يرى شيئًا: مجلد واحد فقط مُرفَق. تثبيت الحزم يعني تشغيل كود طرف ثالث؛ داخل الـ VM هجوم سلسلة التوريد لا يجد ما يسرقه ولا أين ينتشر ([نموذج أمان agent-vm](https://github.com/sylvinus/agent-vm#security-model)). انظر `docs/plan-open-in-vm.md`.

### لماذا VM وليس Docker؟

الحاويات تتشارك نواة جهازك — إفلات حاوية يعني اختراق الجهاز، والوكيل يثبّت حزم غير موثوقة طوال اليوم. الـ VM لها نواة خاصة: حتى root داخلها لا يصل إلى جهازك. والوكيل يظل يحصل على Docker — محرك Docker حقيقي داخل الـ VM (بلا حيل Docker-in-Docker)، فيبني ويشغّل تطبيقات dockerized بحرية داخل العزل.

### شاهد ما يفعله الوكيل في المتصفح

أوامر المتصفح تُنفَّذ في لوحة المتصفح المدمجة بالـ desktop — ترى كل خطوة مباشرة، وتعود لقطات الشاشة للوكيل. لا حاجة لـ headless chrome داخل الـ VM. ويعمل من الجلسات البعيدة أيضًا.

### تحكم كامل بلا تعقيد

- **Reconnect** يشغّل الـ VM المتوقفة بنقرة واحدة.
- نقطة بجانب المجلد: **VM running / stopped**.
- قائمة **⋯**: **Stop VM** يحرر الذاكرة/المعالجات؛ **VM settings…** يغيّر الحجم (VM جديدة — أي شيء خارج المجلد المُرفَق يُعاد ضبطه، مع تنبيه).
- أيقونة المكعب = مساحة VM (السحابة = بعيد، المجلد = محلي). انظر `docs/plan-vm-specs.md`.

### العربية تُقرأ صحيحًا (RTL)

كل سطر يكتشف اتجاهه تلقائيًا: العربية من اليمين لليسار، والكود يبقى من اليسار — في الشات ولوحة الملفات.

---

مبني على [agent-vm](https://github.com/sylvinus/agent-vm) (من sylvinus — شكرًا!) و[Lima](https://lima-vm.io). يشغّل ZakiCode أوامر agent-vm من داخل التطبيق؛ وagent-vm نفسه دون تعديل ويظل يعمل من الطرفية بشكل مستقل.

صيانة المستودع: تجاهل ملفات tsup المؤقتة (`tsup.config.bundled_*.mjs`).

## الإعداد

ثبّت Git و Node.js **24.14.0** و pnpm **10.33.2**. الملف [mise.toml](mise.toml) هو المرجع لإصدارات الأدوات. نفّذ جميع أوامر التطوير والتغليف أدناه من جذر المستودع.

```bash
pnpm bootstrap
```

يثبّت `pnpm bootstrap` تبعيات مساحة العمل، ويجهّز أصول وقت التشغيل المحلية لسطح المكتب، ثم يشغّل `build:bootstrap`.

توجد الشيفرة المصدرية لواجهة سطر الأوامر للوكيل ووقت التشغيل في [apps/zcode-cli/](apps/zcode-cli/) كدليل عادي يُضمّن عند استنساخ المستودع؛ ولا يلزم استنساخ منفصل أو تهيئة Git submodule.

أوامر إعداد وبناء إضافية:

| الأمر                          | الغرض                                                                                                    |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `pnpm install`                 | تثبيت التبعيات                                                                                           |
| `pnpm prepare:desktop-runtime` | تجهيز أصول وقت تشغيل سطح المكتب، بما فيها الأصول البعيدة افتراضيًا                                       |
| `pnpm prepare:remote-assets`   | تجهيز أصول وقت التشغيل البعيدة بشكل منفصل                                                                |
| `pnpm bootstrap:with-remote`   | تجهيز التبعيات والأصول المحلية والبعيدة ثم بناء الحزم ذات الصلة بالتسلسل؛ مع تخطّي حزمة تطبيق سطح المكتب |
| `pnpm build`                   | تشغيل سكربتات بناء كل حزمة في مساحة العمل بشكل تكراري، شاملة خطوات تجهيز الأصول                          |

يتخطى أمر `bootstrap` الافتراضي تجهيز الأصول البعيدة وهو مناسب للتطوير المحلي لسطح المكتب. نفّذ أمر التجهيز المناسب عند العمل على مساحات العمل البعيدة أو التحقق من أصول التوزيعة البعيدة.

## التطوير والاستخدام

### سطح المكتب

```bash
pnpm dev:desktop

# استخدام بيئة الاختبار
pnpm dev:desktop:test
```

يعتمد `pnpm dev:desktop` افتراضيًا على `pnpm dev:desktop:prod` ويستخدم إعدادات الخدمات الإنتاجية. يجهّز سكربت التشغيل أصول وقت التشغيل المحلية، ويبني وكيل سطح المكتب، ثم يشغّل Electron ومراقبي الشيفرة المصدرية.

عيّن `ZCODE_DATA_BASE_DIR` لاستخدام دليل بيانات تطوير منفصل. مثلًا على macOS / Linux:

```bash
ZCODE_DATA_BASE_DIR="$HOME/.zcode-dev-home" pnpm dev:desktop:test
```

### تطوير الويب

استخدم وضع التطوير عند تعديل شيفرة Web أو الخدمات الخلفية:

```bash
pnpm dev:web

# تعيين مساحة عمل الخدمة الخلفية (macOS / Linux)
ZCODE_SERVER_WORKSPACE=/path/to/project pnpm dev:web
```

يشغّل هذا خادم تطوير Web ‏(الافتراضي: `http://localhost:5173`) والخدمة الخلفية (الافتراضي: `http://localhost:3030`). افتح خادم تطوير Web في المتصفح؛ تُمرَّر طلبات `/ws` و `/api` العامة إلى الخدمة الخلفية المحلية، بينما يُمرَّر `/api/v1/oauth/token` بشكل منفصل إلى خدمة المنتج المُهيّأة.

بعد تعديل شيفرة الوكيل، نفّذ `pnpm --filter @zcode/cli... build` وأعد تشغيل الخدمة. للتحقق من التوزيعة الكاملة، فك ضغطها وشغّلها كما هو موصوف في قسم التغليف ← توزيعة ZCode CLI أدناه.

### توزيعة ZCode CLI

تتضمن توزيعة سطر الأوامر كلًّا من TUI وعميل Web والوكيل خلف أمر `zcode` واحد. بدون وسائط تبدأ واجهة TUI؛ و`--web` في البداية تبدأ وضع Web؛ وكل الوسائط الأخرى تمرر إلى واجهة الوكيل القائمة. يعمل الوضعان محليًا دون Electron.

```bash
# بدء واجهة الطرفية افتراضيًا
zcode

# بدء واجهة الويب
zcode --web

# تعيين المشروع والمنفذ دون فتح المتصفح تلقائيًا
zcode --web --workspace /path/to/project --port 3030 --no-open

# عرض خيارات CLI أو Web
zcode --help
zcode --web --help
```

في وضع Web، يستخدم الدليل الحالي مساحةً للعمل، ويستمع على `127.0.0.1` دون مصادقة برمز افتراضيًا، ويختار منفذًا متاحًا، ويفتح المتصفح. استخدم الرابط المطبوع في الطرفية وأوقف الخدمة بـ `Ctrl+C`. للوصول عبر الشبكة المحلية استخدم `--host 0.0.0.0`؛ الاستماع على عنوان غير محلي يولّد رمز وصول افتراضيًا — استخدم الرابط الحاوي على الرمز المطبوع في الطرفية. عيّن رمزًا بـ `--token`، أو عطّل مصادقة الرمز بـ `--no-token`.

عند بدء مدخل HTTP لخدمة Web العامة مباشرة، هيّئ مصادقة API/WebSocket عبر `ZCODE_SERVER_AUTH_TOKEN`. وعند إنشاء الخدمة برمجيًا استخدم الخيار `authToken`.

انظر قسم التغليف أدناه لتعليمات البناء. ينشئ `pnpm build:zcode` التوزيعة فقط ولا يستبدل أمر `zcode` موجودًا في `PATH`. إذا كان الأمر يشير إلى تثبيت أقدم أو مستودع آخر، تحقّق عبر `command -v zcode` على macOS / Linux أو `where.exe zcode` على Windows.

### تطوير شيفرة CLI المصدرية

استخدم المدخل المصدري عند تطوير TUI أو الوكيل:

```bash
pnpm --filter @zcode/cli dev --help
pnpm --filter @zcode/cli dev

# بناء CLI وتبعيات مساحة العمل الخاصة به
pnpm --filter @zcode/cli... build
node apps/zcode-cli/packages/cli/dist/zcode.cjs --help
```

يشغّل هذا المدخل واجهة الوكيل مباشرة ولا يعالج مفتاح `--web` الخاص بالتوزيعة. استخدم `pnpm dev:web` لتطوير الويب، أو `bin/zcode.mjs` المستخرج كما هو موضح أدناه لاختبار الأمر الموحّد.

## الإعدادات

يوفر الملف [.env.example](.env.example) في الجذر نماذج لعناوين URL للخدمات وإعدادات البناء. انسخه إلى `.env` حسب الحاجة وضع التجاوزات المحلية في `.env.local`. اختر بيئة تطوير سطح المكتب عبر `dev:desktop:test` أو `dev:desktop:prod`.

| الإعداد                              | الغرض                                                                         |
| ------------------------------------ | ----------------------------------------------------------------------------- |
| `ZCODE_DATA_BASE_DIR`                | الدليل الأساسي لبيانات التطبيق، وتُخزَّن في الدليل الفرعي `.zcode/` التابع له |
| `ZCODE_SERVER_WORKSPACE`             | مسار مساحة عمل الخدمة الخلفية للويب                                           |
| `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE` | مسار ملف تهيئة مزوّدين محلي؛ يستخدم التهيئة المدمجة عند عدم التعيين           |
| `ZCODE_DIST_BASE_URL`                | عنوان URL الأساسي للتنزيل الذي يستخدمه مثبّت توزيعة CLI                       |

يمكن تعيين متغيرات التشغيل صراحةً في بيئة أمر التشغيل. انظر [config/README.md](config/README.md) للتهيئة الافتراضية المشحونة مع العميل.

## التغليف

انظر [third-party/README.md](third-party/README.md) لتوليد الإشعارات وفحوص التوزيعة ومواضع تضمين الإشعارات في كل توزيعة.

### سطح المكتب

```bash
pnpm bundle:desktop

# تعيين المنصة المستهدفة ومعمارية المعالج
pnpm bundle:desktop -- --os win --arch x64

pnpm bundle:desktop -- --help
```

الهدف الافتراضي هو macOS arm64 والدليل الافتراضي للإخراج هو `packages/desktop/dist/`. يقبل `--os` القيم `mac` أو `win` أو `linux`؛ ويقبل `--arch` القيم `x64` أو `arm64`. يتطلب التغليف والتوقيع أدوات وإعدادات المنصة المستهدفة.

### توزيعة ZCode CLI

نفّذ `pnpm build:zcode` لبناء CLI/TUI والخدمة الخلفية وعميل Web، وجمع مكتبات TUI الأصلية و workers وتبعيات وقت التشغيل، ثم تجميع التوزيعة. لا يزال تشغيل التوزيعة يتطلب Node.js؛ استخدم الإصدار المحدد في `mise.toml`.

قبل التغليف، عيّن عنوان URL الأساسي للتنزيل عبر `ZCODE_DIST_BASE_URL` في `.env` أو `.env.local` أو بيئة العملية، أو مرّره عبر `--base-url`. العنوان أدناه نموذجي؛ استبدله بعنوان الاستضافة عند النشر:

```bash
pnpm build:zcode --base-url https://downloads.example.com/zcode/

# عندما يكون ZCODE_DIST_BASE_URL مهيأً بالفعل
pnpm build:zcode

# إعادة تجميع مخرجات بناء الوكيل والخدمة الخلفية و Web الموجودة
pnpm build:zcode --skip-build

# عرض خيارات الإصدار ودليل الإخراج وغيرها
pnpm build:zcode --help
```

الإصدار الافتراضي هو إصدار `package.json` في الجذر. يُكتب الإخراج في `dist/zcode/`:

- `releases/<version>/zcode-<version>.tar.gz`: حزمة وقت التشغيل.
- `releases/<version>/sha256.txt`: ملف بصمات التحقق.
- `latest.json` و `install.sh`: فهرس الإصدارات والمثبّت.

ارفع الدليل كاملًا إلى عنوان URL التنزيل المُهيّأ. ينزّل المثبّت حزمة وقت التشغيل من ذلك العنوان، ويثبّتها افتراضيًا في `~/.zcode/runtime`، وينشئ أمر `zcode` في `~/.local/bin`. تجاوز هذه الدلائل عبر `ZCODE_DIST_HOME` و `ZCODE_DIST_BIN_DIR` على التوالي.

على مستخدمي Lite الحاليين التحويل إلى أمر البناء الجديد ومتغيرات البيئة والمثبّت الجديدة. التثبيت لا يحذف دلائل Lite القديمة ولا يرحّل بيانات الجلسات أو يحذفها.

لاختبار بناء مغلّف محليًا، فك ضغطه وشغّله مباشرة دون رفع أو تثبيت:

```bash
zcode_version=$(node -p "require('./dist/zcode/latest.json').version")
mkdir -p dist/zcode/debug
tar -xzf "dist/zcode/releases/$zcode_version/zcode-$zcode_version.tar.gz" \
  -C dist/zcode/debug
# بدء TUI افتراضيًا
node dist/zcode/debug/zcode/bin/zcode.mjs

# بدء وضع Web
node dist/zcode/debug/zcode/bin/zcode.mjs --web \
  --workspace "$PWD" --port 3030 --no-open
```

افتح `http://127.0.0.1:3030` للتحقق من المسار الكامل، بخدمة خلفية واحدة تخدم صفحات Web وتشغّل الوكيل. يجب أن يكون المنفذ متاحًا؛ إذا كان `pnpm dev:web` يعمل بالفعل فاختر `--port` آخر.

## بنية المستودع

| الدليل                                               | المسؤولية                                                            |
| ---------------------------------------------------- | -------------------------------------------------------------------- |
| `packages/desktop`                                   | ‏Electron Main و Host و Renderer وتغليف سطح المكتب                   |
| `packages/web`                                       | عميل Web                                                             |
| `packages/server`                                    | خدمات HTTP / WebSocket والاتصالات البعيدة                            |
| `packages/zcode-server-cli`                          | تشغيل الخادم المستقل وإدارة العمليات                                 |
| `packages/ui`                                        | مكوّنات React المشتركة و hooks وحالة Zustand                         |
| `packages/services`                                  | خدمات الأعمال والتخزين الدائم                                        |
| `packages/shared`, `packages/rpc`, `packages/client` | البروتوكولات والأنواع المشتركة، إطار RPC، و SDK عميل الوكيل          |
| `packages/provider`, `packages/provider-node`        | قدرات المزوّدين المشتركة وتطبيقات Node                               |
| `apps/zcode-cli`                                     | واجهة الوكيل CLI و TUI ووقت التشغيل والأدوات                         |
| `scripts`, `config`, `third-party`                   | سكربتات البناء والصيانة، التهيئة المدمجة، ومواد إشعارات الطرف الثالث |
